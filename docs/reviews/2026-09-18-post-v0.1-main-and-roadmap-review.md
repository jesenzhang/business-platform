## 2. Current implementation finding

v0.1 is a real runnable Document Intelligence/platform foundation, not merely an architecture prototype:

- production OIDC/JWT authentication;
- Document Revision / processing / Evidence;
- durable workers with lease/fence/recovery;
- real model-provider integration;
- Runtime Audit / Integrity / Controlled Repair;
- REST/OpenAPI, CLI, React console and narrow read-only MCP;
- observability and backup/restore evidence.

However, implementation density is highly uneven.

Identity/authorization gap:

- AuthenticatedPrincipal and trusted tenant/user context exist.
- A small ManagementPermission enum protects Governance endpoints.
- crates/identity is still a TODO skeleton.
- crates/organization is still a TODO skeleton.
- there is no complete PlatformUser/TenantMembership/Role/Permission/RoleBinding/ResourceScope lifecycle.
- OIDC roles are claims, not a complete internal business authorization system.

Business-domain gap:

- Contract/Finance/Approval/Project and several other business crates remain largely skeletons.
- No real Contract vertical slice currently validates Business Application packaging, internal authorization, Document/Evidence and Console together.

Agent gap:

- agent-adapter provides a narrow read-only MCP surface.
- Workspace/Conversation/Turn/AgentRun/Capability/Observation are not implemented.
- Activating the old PLAN-0006 directly would build Agent delegation on top of incomplete business authorization and mostly placeholder business domains.

## 4. Architecture decision after review

Do not rewrite the accepted architecture. Change execution order.

~~~text
v0.1
 -> PLAN-0013 Identity / Authorization
 -> Contract Business Vertical Slice
 -> Knowledge/Evidence Projection when business Q&A requires it
 -> PLAN-0006 Revision 1 Workspace / Agent
 -> Controlled Write ActionPlan
 -> Analytics / Approval / Finance / Legal
~~~

Rationale:

1. Authentication already works; the missing layer is internal business authorization.
2. Contract is the first real business module needed to validate platform abstractions.
3. Agent Capability must be a narrower delegation of real user authority, not a replacement for missing RBAC/resource policy.
4. Agent Tools need real Published Application Contracts rather than TODO domains.
5. Platform/module abstractions are already ahead of product/business implementation; further generic runtime expansion should wait for evidence from real vertical slices.

## 6. PLAN-0013 boundary

PLAN-0013 is Proposed / NEXT CANDIDATE, not Active.

It must implement the minimum internal authorization foundation:

- PlatformUser / external identity mapping;
- TenantMembership;
- minimal OrganizationUnit/OrganizationMembership;
- PermissionDefinition;
- RoleDefinition / RolePermission;
- RoleBinding;
- ResourceScope;
- Authorize / ExplainDecision;
- compatibility migration from fixed ManagementPermission;
- minimal management REST/Console;
- audit, negative security tests and real PostgreSQL E2E.

It must not build password/MFA/OAuth issuance, full HR, generic ReBAC/ABAC DSL, Contract domain or Agent Workspace.

## 7. PLAN-0006 Revision 1 gate

PLAN-0006 remains Proposed / BLOCKED until both are Integrated:

- PLAN-0013;
- first Contract Business Vertical Slice.

Its first Agent surface is read-only and uses a deterministic Compiled Agent Tool Catalog plus per-turn authorization/capability resolution. Tool identity collision is fail-closed; Tool targets are Published Application Queries; no direct DB/SQL/Shell/arbitrary HTTP access.

Supply-chain hardening should replace the generic compose image quay.io/minio/minio:latest with an explicitly reviewed immutable version/digest. This is intentionally not mixed into this documentation-only roadmap change.

## 9. Review result

PASS for documentation/roadmap integration.

The reviewed main changes do not invalidate the existing architecture. The material correction is execution order: complete platform-owned authorization first, validate it with Contract, then implement Workspace/Agent on real authorization and business contracts.
